**Blueprint (SDV)** — Eclipse SDV Blueprints project: a reproducible end-to-end showcase repo combining several SDV projects for one use case. [[sdv-blueprints-overview]]
**FMS / rFMS** — Fleet Management Standard (truck OEM) and its REST API; the Fleet Management blueprint exposes rFMS 4.0 over HTTP on :8081. [[sdv-blueprints-overview]]

**CARL** — openDuT backend server (gRPC API, serves LEA) managing peers, devices, clusters; acronym expansion unverified. [[opendut-overview]]
**EDGAR** — openDuT edge agent on the machine/Pi next to the DUT; sets up VPN, GRE bridges, CAN bridges, runs executors. [[opendut-overview]]
**LEA** — openDuT web UI (Rust/Leptos, client-side rendered) served by CARL. [[opendut-overview]]
**CLEO** — openDuT CLI (`opendut-cleo`), incl. `apply` of YAML descriptors. [[opendut-quickstart]]

**NetBird** — WireGuard-based VPN (mgmt/signal/relay) used by openDuT for peer connectivity. [[opendut-overview]]

**Ankaios** — Eclipse workload/container orchestrator for embedded and automotive (server + agents + `ank` CLI, podman/containerd runtimes). [[ankaios-overview]]

**Startup manifest** — YAML state file (apiVersion v1) the Ankaios server loads at start, e.g. /etc/ankaios/state.yaml. [[ankaios-quickstart]]
**podman-kube** — Ankaios runtime that deploys Kubernetes pod YAML via `podman play kube`. [[ankaios-overview]]

**zenoh-pico** — C implementation of Zenoh for MCUs. [[zenoh-overview]]

**Muto** — Eclipse adaptive orchestrator for ROS 2 stacks (Agent, Composer). [[muto-overview]]
**ThreadX** — Eclipse safety-certified RTOS (with NetX Duo network stack). [[threadx-overview]]
**OpenBSW** — Eclipse OpenBSW: C++ automotive microcontroller basic-software stack (async, lifecycle, CAN/DoCAN, UDS, DoIP server, console, logging). [[openbsw-overview]]
**BSW** — Basic Software: the OS-near layer of an ECU (drivers, comms stack, diagnostics) beneath the application. [[openbsw-overview]]
**DoCAN** — Diagnostics over CAN (ISO 15765-2 transport for UDS). [[openbsw-overview]]
**DoIP** — Diagnostics over IP (ISO 13400-2); TCP/UDP port 13400; carries UDS over Ethernet. [[openbsw-overview]]
**CDA** — Classic Diagnostic Adapter (OpenSOVD): translates SOVD REST to UDS/DoIP. [[openbsw-integration-notes]]
**vcan** — Linux SocketCAN virtual CAN interface used by the POSIX OpenBSW build. [[openbsw-quickstart]]

**AutoSD** — Automotive Stream Distribution, CentOS-Stream-based upstream preview of Red Hat In-Vehicle OS. [[autosd-overview]]
**BlueChi** — multi-node/multi-partition systemd service controller used in AutoSD. [[autosd-reference]]
**bootc** — bootable container images; OS updated via `bootc switch/update`. [[autosd-howto]]
**Quadlet** — podman systemd generator turning `*.container` files into services. [[autosd-howto]]
**QM partition** — Quality-Managed nested rootfs with its own systemd/podman for non-safety workloads. [[autosd-overview]]
**RHIVOS** — Red Hat In-Vehicle Operating System, downstream product of AutoSD. [[autosd-overview]]
**SolutionPlan** — one-page team README template (team, core idea, process, QA, communication, decisions) used in Chapter 3. [[chapter3-retrospective]]
**sdv_lab** — Chapter 3 Virtual SDV Lab starter: CARLA/AAOS on a shared laptop plus Rust/Python workloads under Ankaios over uProtocol, Zenoh or MQTT. [[chapter3-retrospective]]
**Maestro challenge** — 2023/2024 challenge: build a scenario on a provided in-vehicle stack and orchestrator (Ankaios/BlueChi, later Symphony). [[earlier-chapters]]
**AZ3166** — MXChip IoT DevKit board used for ThreadX challenges in 2024 and 2025. [[earlier-chapters]]
**S-CORE** — Eclipse Safe Open Vehicle Core: open-source, safety-oriented (ISO 26262, up to ASIL B) middleware stack on POSIX OS (Linux, QNX) in C++/Rust, built with Bazel. [[s-core-overview]]
**LoLa (mw::com)** — S-CORE's zero-copy shared-memory IPC ("Low Latency"), partial ara::com skeleton/proxy API; S-CORE's core IPC (not iceoryx2). [[s-core-overview]]
**FEO** — Fixed Execution Order framework in S-CORE: activities (init/step/shutdown) statically mapped to threads/processes, deterministic task chains, reprocessing; com backends iceoryx2, Linux shm, mw::com. [[s-core-overview]]
**Kyron** — S-CORE's safety-focused async runtime for Rust with configurable execution engines and dedicated workers. [[s-core-overview]]

**docs-as-code** — S-CORE's Sphinx + sphinx-needs tooling where requirements, architecture and tests are traceable objects checked in CI. [[s-core-howto]]
**Ferrocene** — Qualified Rust toolchain used by S-CORE Bazel builds. [[s-core-reference]]
**EBcLfSA** — Elektrobit corbos Linux for Safety Applications; an S-CORE target image (aarch64, QEMU/RPi). [[s-core-integration-notes]]
**Kanto** — Eclipse Kanto, Go edge stack: containerd-based container management plus Hono/Ditto cloud connector; code frozen since mid-2024. [[kanto-overview]]
**kanto-cm** — CLI of Kanto container management. [[kanto-overview]]
**CANought** — Eclipse sub-project extending Kanto with CAN translation and uProtocol C++ client/server; dormant since 2025-04. [[kanto-overview]]
**Velocitas** — Eclipse toolchain/SDK for vehicle apps on KUKSA with devcontainer, templates and CLI; maintenance mode in 2026. [[velocitas-overview]]
**Vehicle App** — QM containerised application using the Velocitas SDK and a VSS vehicle model. [[velocitas-overview]]
**devenv-runtimes** — Velocitas package that starts databroker/MQTT/seat service locally or via Kanto; pins old images. [[velocitas-overview]]
**autowrx** — Eclipse open-source implementation of digital.auto (playground.digital.auto), browser prototyping on VSS. [[autowrx-overview]]
**sdv-runtime** — autowrx Docker image bundling KUKSA databroker 0.4.4, Velocitas Python SDK and kit manager that connects to the playground. [[autowrx-overview]]
**dreamKIT** — digital.auto PoC hardware (NXP S32G + Jetson Orin) that runs playground apps. [[autowrx-overview]]
**SommR** — Eclipse SOME/IP implementation in Rust; archived, repository empty. [[sommr-overview]]
**SOME/IP** — Scalable service-Oriented MiddlewarE over IP, AUTOSAR-era service protocol on automotive Ethernet. [[sommr-overview]]
**Chariott** — Microsoft-originated Rust intent-brokering/service-discovery service; dormant since 2025-04, not archived. [[chariott-overview]]
**Ibeji** — Microsoft-originated in-vehicle digital twin service using DTDL; dormant since 2024. [[chariott-overview]]
**Agemo** — Chariott-org dynamic pub/sub (managed subscribe) service. [[chariott-overview]]
**Freyja** — Ibeji-org synchroniser between in-vehicle and cloud digital twins. [[chariott-overview]]
**DTDL** — Digital Twins Definition Language (JSON-LD), the model format used by Ibeji. [[chariott-overview]]
**SDV WG landscape** — master list of 37 Eclipse SDV WG projects with activity level, dormant ones flagged. [[sdv-landscape-overview]]
**iceoryx2** — Eclipse zero-copy, lock-free shared-memory IPC library with a Rust core and C/C++/Python bindings; successor of iceoryx classic; no central daemon. [[iceoryx2-overview]]
**iceoryx classic** — The original C++ Eclipse iceoryx (v1/v2.x, RouDi daemon); in maintenance mode, EOL after iceoryx2 1.0. [[iceoryx2-overview]]
**ZeroCopySend** — iceoryx2 Rust trait/derive macro marking a payload type as shared-memory safe (self-contained, `#[repr(C)]`, no heap/pointers, no Drop). [[iceoryx2-howto]]
**iceoryx2 Node** — Process-local iceoryx2 entity owning services/ports, used for liveness and dead-node cleanup. [[iceoryx2-overview]]
**iceoryx2 Service** — Named iceoryx2 channel with one messaging pattern (pub/sub, request/response, event, blackboard) and static QoS limits. [[iceoryx2-overview]]
**Blackboard (iceoryx2)** — iceoryx2 messaging pattern: a shared-memory key-value store with one writer and many readers. [[iceoryx2-reference]]
**iceoryx2 link / tunnel** — iceoryx2 component extending services beyond one shared-memory domain; the tunnel backend connects iceoryx2 hosts via a carrier such as Zenoh (`iox2-link-tunnel-zenoh`); prototype. [[iceoryx2-integration-notes]]
**iox2** — iceoryx2 command-line tool (`iox2 service list|details|subscribe|hz|record|replay`, `iox2 node`, `iox2 config`, `iox2 link`). [[iceoryx2-reference]]
**dev_permissions** — iceoryx2 build feature making all shared-memory resources world-accessible so different Unix users can communicate; development only. [[iceoryx2-howto]]
**LoLa** — "Low Latency", S-CORE's own C++ zero-copy shared-memory implementation of ara::com (`mw::com`); not based on iceoryx2. [[iceoryx2-integration-notes]]
**FEO** — Fixed Execution Order framework in Eclipse S-CORE (Rust); its `feo-com` has an iceoryx2 pub/sub backend. [[iceoryx2-integration-notes]]
**VSS (Vehicle Signal Specification)** — COVESA tree-structured data model of vehicle signals (`Vehicle.Speed`, ...) written in `.vspec` YAML; current release 6.1 (2026-09-17). [[vss-kuksa-overview]]
**vspec / vss-tools** — COVESA Python CLI (`vspec export json|csv|protobuf|ddsidl|...`) that validates VSS, applies overlays and exports artifacts. [[vss-kuksa-reference]]
**VSS overlay** — extra `.vspec` file passed with `-l` that adds, changes or deletes nodes of the standard catalog; order matters. [[vss-kuksa-howto]]
**VSS profile** — overlay that reshapes the standard catalog for a vehicle type, e.g. `overlays/profiles/motorbike.vspec`. [[vss-kuksa-howto]]
**sensor / actuator / attribute (VSS)** — VSS leaf types: measured value / value that can be requested to change / static value. [[vss-kuksa-reference]]
**KUKSA Databroker** — Eclipse KUKSA Rust gRPC server holding live VSS values in memory (port 55555); v0.7.1. [[vss-kuksa-overview]]
**kuksa.val.v2** — current KUKSA gRPC API (GetValue, PublishValue, Subscribe, Actuate, OpenProviderStream); v1 deprecated, sdv.databroker.v1 removed in 0.7.0. [[vss-kuksa-reference]]
**KUKSA provider** — process that feeds sensor values into, and executes actuation requests from, the databroker (CAN, CSV, SOME/IP, DDS, Zenoh providers). [[vss-kuksa-howto]]
**Target value vs actuation (KUKSA)** — v1 stores a wanted "target" value; v2 forwards an "actuation" to the registered provider; the two channels do not interoperate. [[vss-kuksa-howto]]
**databroker-cli** — KUKSA Rust CLI for the databroker (v1 only, needs a TTY). [[vss-kuksa-quickstart]]
**kuksa-client** — KUKSA Python SDK and interactive CLI (PyPI, v0.6.0). [[vss-kuksa-quickstart]]
**HI / LI application** — High-/low-integrity process on EBcLfSA; HI apps are statically linked, ELF-header-marked (`lisa-elf-enabler`) and started by the HI init `cflinit`, while LI userland is started by `crinit`. [[hackfest-score-reference-integration]]
**MDD** — FlatBuffers-based diagnostic database consumed by the OpenSOVD CDA, converted from ODX/PDX by `odx-converter` (or generated directly); preferred over ODX for size. [[hackfest-openbsw-playground]]
**ODX / PDX** — ISO 22901 XML diagnostic description (ODX) and its zipped container (PDX). [[hackfest-openbsw-playground]]
**Adapter module (S-CORE)** — HackFest pattern: an S-CORE Bazel repo that fetches an unmodified external Cargo project and injects BUILD files so it builds with S-CORE toolchains; since superseded by native Bazel in the CDA. [[hackfest-score-inc-diagnostics]]
**FaultLib / DiagLib** — OpenSOVD/S-CORE libraries through which apps report faults (FaultLib) and implement diagnostic services (DiagLib, S-CORE `score/mw/diag`) toward the SOVD server. [[hackfest-score-inc-diagnostics]]
**UDS2SOVD** — OpenSOVD proxy letting legacy UDS testers talk to a SOVD stack; on hold as of May 2026. [[hackfest-esslingen-2026]]
**FLXC1000** — Back-to-the-Future-themed "Flux Capacitor" demo ECU (MDD + OpenBSW overlay) on the OpenBSW-Playground branch `features/jkk_FLUX1000`. [[hackfest-openbsw-playground]]
**SOVD (Service-Oriented Vehicle Diagnostics)** — REST/HTTP+JSON diagnostics API (ASAM SOVD 1.x, standardised as ISO 17978-1/-3:2026); entities (areas, components, apps, functions) with resource collections data, faults, operations, configurations, modes, locks, bulk-data, logs. [[opensovd-overview]]
**OpenSOVD** — Eclipse (incubating) Rust implementation of SOVD: opensovd-core (server/gateway/client), Classic Diagnostic Adapter, fault-lib/DFM, odx-converter. [[opensovd-overview]]
**DFM (Diagnostic Fault Manager)** — OpenSOVD central component that receives fault-lib reports over iceoryx2, applies debounce/aging/operation cycles, persists DTC state and serves SOVD-shaped faults. [[opensovd-howto]]
**SOVD entity / resource collection** — an addressable diagnostic object (`/components/{id}`, `/apps/{id}`, ...) and the sub-paths it offers (`/data`, `/faults`, `/operations`, ...). [[opensovd-reference]]
**DTC status mask** — ISO 14229 status byte of a DTC (bit0 testFailed, bit2 pendingDTC, bit3 confirmedDTC, bit7 warningIndicatorRequested, ...); exposed by the OpenSOVD CDA as `status.mask`. [[opensovd-reference]]
**Variant detection (CDA)** — CDA step that identifies which ODX variant an ECU runs; until it concludes, ECU resources return 503 `communication-not-ready`. [[opensovd-quickstart]]
**opensovd-gateway** — opensovd-core server binary (`ghcr.io/eclipse-opensovd/opensovd-gateway`, port 7690, `--mock` topology). [[opensovd-quickstart]]
**uProtocol** — Eclipse transport-agnostic, layered communication spec (addressing, message envelope, pub/sub, notification, RPC) over Zenoh, MQTT5, SOME/IP etc. [[uprotocol-overview]]
**uEntity** — A uProtocol software component (application or service) identified by authority, ue_id, version. [[uprotocol-overview]]
**UUri** — uProtocol address: authority_name + ue_id (type|instance) + ue_version_major + resource_id; string form `//authority/ID/VER/RES`. [[uprotocol-overview]]
**UMessage** — uProtocol message: UAttributes (id, type, source, sink, priority, ttl, ...) plus optional payload. [[uprotocol-overview]]
**uP-L1 / uP-L2 / uP-L3** — uProtocol transport layer (UTransport), communication layer (Publisher/Subscriber/Notifier/RPC), core services layer (uSubscription, uDiscovery, uTwin). [[uprotocol-overview]]
**uStreamer** — Gateway that forwards uProtocol messages between transports by authority; pub/sub only for topics in a (static) subscription list. [[uprotocol-howto]]
**uSubscription** — uProtocol L3 service that tracks subscriptions between uEntities, incl. remote ones; spec v3/v4. [[uprotocol-reference]]
**UTransport** — The L1 interface (send/receive/register_listener) every transport library implements. [[uprotocol-reference]]
**RIHS01** — ROS Interface Hashing Standard v1: SHA-256 type hash of a ROS 2 interface (REP-2011), carried in discovery and in rmw_zenoh key expressions. [[type-hash-is-the-contract-bridges-must-not-erase-it]]
**VDA 5050** — VDA/VDMA open interface between AGV fleet control and vehicles over MQTT (order, state, factsheet, connection with last will). [[vda5050-announce-state-and-last-will]]
**FEO** — S-CORE Fixed Execution Order framework for cyclic, ordered activities (ASIL_B target). [[executor-is-not-a-schedule-fix-the-order-or-prove-it]]
**aggregate (VSS)** — Branch keyword requesting atomic read/write of its signals; undefined in the standard catalog, only sensible as a deployment overlay hint. Structs are the preferred coherent set. [[coherence-is-a-set-property-declared-in-the-model]]
**fka (VSS)** — "formerly known as": attribute that keeps a static id stable across a rename or move; the id hashes the old name. [[derive-ids-from-layout-not-from-prose]]
**network_serialization (VSS profile)** — Overlay key mapping a VSS signal to a DBC/ARXML signal, with interval, endianness and math/representation transforms. [[mappings-are-overlays-the-source-model-stays-pristine]]
**Placement manifest** — artefact stating which node produces which signal set at which cadence; direction derived per node. [[placement-is-a-manifest-not-a-model-edit]]
**QM partition** — AutoSD nested rootfs with its own systemd and podman for non-safety workloads, supervised from the root side. [[freedom-from-interference-is-a-stack-of-layers]]
**ADD_COND_RUNNING** — Ankaios dependency condition: the dependency's container is running; not an application readiness claim. [[one-supervisor-per-node-readiness-is-the-apps-claim]]
**bdSeq** — Sparkplug B birth/death sequence metric: the same value goes in the MQTT Will (NDEATH) and the NBIRTH, so hosts can tell a current death from a stale one. [[a-vehicle-is-gone-when-its-death-certificate-says-so]]
**Liveliness token** — Zenoh primitive tied to a session; subscribers see Put on appearance and Delete when the session ends or lease expires. [[a-vehicle-is-gone-when-its-death-certificate-says-so]]
**Rebirth (Sparkplug)** — NCMD `Node Control/Rebirth` asking an edge node to republish its NBIRTH. [[a-vehicle-is-gone-when-its-death-certificate-says-so]]
**FTTI (fault tolerant time interval)** — ISO 26262: the time from a fault occurring until a hazardous event could occur if no safety mechanism acts; bounds detection + reaction + any hold-last window. [[deciding-on-a-bad-state-is-wrong-not-degraded]]
**Freedom from interference (FFI)** — ISO 26262: absence of cascading failures from a lower-integrity element into a higher one; argued on three axes: memory, timing/execution, exchange of information. [[freedom-from-interference-has-three-axes]]
**Black channel** — IEC 61508 / IEC 61784-3 principle: the transport is untrusted and a safety layer (CRC, counter, id, timeout) on top detects its failures. [[freedom-from-interference-has-three-axes]]
**SOTIF (ISO 21448)** — Safety of the intended functionality: hazards from functional insufficiencies and triggering conditions, as opposed to faults (ISO 26262). [[evidence-is-a-linked-record-not-a-log]]
**Golden vector** — a checked-in input recording plus its expected output, replayed in CI and against independent implementations. [[record-at-the-seam-replay-with-the-original-clock]]
**Capability token** — Signed statement "the bearer may do X on Y until T"; the server maps each route to a required capability and asks one injected authorizer. [[the-route-names-the-capability-the-token-carries-it]]
**x5c** — JWS header carrying the signer's X.509 chain (leaf first), validated by the recipient against a pinned root (RFC 7515 §4.1.6). [[verify-offline-against-a-pinned-root]]
**Time floor** — Persisted lower bound on wall time, raised only from signed artefacts; checks use `now = max(rtc, floor)`. [[time-only-moves-forward-from-signed-evidence]]
**Attenuation** — Narrowing a delegated token's authority at each hop; a hop may restrict, never add. [[authority-only-narrows-across-hops]]
**SecOC** — AUTOSAR Secure Onboard Communication: truncated CMAC plus freshness value per PDU, authenticating the sender (contrast E2E, which detects faults only). [[e2e-proves-integrity-secoc-proves-the-sender]]
**Freshness value** — SecOC counter or timestamp included in the MAC so replays fail; only its low bits travel in the frame. [[e2e-proves-integrity-secoc-proves-the-sender]]
**Key service** — Narrow process or HSM slot that performs secret operations (seed-key, signing) on request, so the diagnostic server holds no secrets. [[the-diagnostic-server-holds-no-secrets]]
**CEK (content-encryption key)** — random per-release symmetric key that encrypts an update payload once; each device receives only the CEK wrapped to its own key (ECDH-ES + AES-KW). [[encrypt-once-wrap-per-device]]
**Director / Image repository (Uptane)** — the online, per-vehicle repository that says which ECU installs what, versus the offline-keyed repository that vouches for the bytes; ECUs install only when both agree. [[two-keys-who-may-run-what-may-install]]
**RXSWIN** — R-series software identification number under UN R156, linking installed software to a type approval; must be readable from the vehicle. [[one-transaction-two-delivery-paths]]
**Security version** — anti-rollback floor that rises only when a vulnerability is fixed and only on commit; distinct from build version and manifest sequence number. [[security-version-is-not-build-order]]
**Singleshot component** — part updated in place with no fallback (HSM keys, fuses, single-bank MCU, merged Virtual A/B); never mixed with banked parts in one transaction. [[never-mix-banked-and-singleshot]]
**SUIT** — IETF Software Updates for IoT: RFC 9019 (architecture), RFC 9124 (information model) and the CBOR/COSE manifest draft with command sequences interpreted on the device. [[the-manifest-programs-the-device]]
**SUMS** — Software Update Management System, the organisational process UN R156 certifies. [[one-transaction-two-delivery-paths]]
**TUF** — The Update Framework: root, targets, snapshot and timestamp roles defending against freeze, rollback and mix-and-match attacks; Uptane builds on it. [[versions-ratchet-even-when-the-clock-lies]]
**Data ID (E2E)** — AUTOSAR E2E identifier of a protected data element, sent explicitly or mixed only into the CRC (implicit); detects insertion, wrong addressing and (with the CRC) masquerade. [[the-transport-is-untrusted-the-consumer-checks-carry-safety]]
**OKSOMELOST / MaxDeltaCounter** — AUTOSAR E2E check status for a counter jump within the configured maximum delta (loss tolerated and counted); beyond it the status is WRONGSEQUENCE. [[loss-is-counted-at-the-consumer-never-hidden-by-the-buffer]]
**Safe overflow (iceoryx2)** — Service setting (`enable_safe_overflow`, default true) under which a full subscriber buffer overwrites its oldest sample instead of blocking the publisher. [[loss-is-counted-at-the-consumer-never-hidden-by-the-buffer]]
**Sealed frame** — The producer's payload plus its E2E header, source id, counter and pass stamp; hops may re-stamp the envelope around it but never decode or re-seal it. [[forward-sealed-frames-byte-for-byte]]
**NAME (J1939)** — 64-bit self-declared ECU identity (function, instances, manufacturer, identity number); the 8-bit source address is only a contested lease, lowest NAME wins. [[claim-the-address-keep-the-name]]
**Address claim (J1939-81)** — power-up procedure: send Address Claimed (PGN 60928), wait 250 ms for contests; late joiners send Request (PGN 59904). [[claim-the-address-keep-the-name]]
**SOME/IP-SD** — SOME/IP Service Discovery: Find/Offer/StopOffer/Subscribe entries keyed by service id, instance id, major, minor, with TTL (0 = stop). [[pin-the-major-wildcard-the-instance]]
**Reboot Flag (SOME/IP-SD)** — header bit set until the SD Session ID first wraps; lets peers detect a provider reboot faster than any TTL. [[a-reboot-is-a-new-session-not-the-same-producer]]
**TypeInformation (DDS-XTypes)** — MINIMAL and COMPLETE type-hash identifiers carried in SEDP endpoint discovery; the full TypeObject is fetched via TypeLookup. [[match-on-the-type-descriptor-never-fall-back-to-the-name]]
**ServiceHash (iceoryx2)** — id of a service derived from messaging pattern + service name; renaming a service is a new identity. [[digest-for-the-content-tag-for-the-name]]
**AttributeVerifier (iceoryx2)** — requirements a consumer places on service attributes when opening; mismatch fails with `IncompatibleAttributes`. [[open-on-arrival-age-by-your-own-deadline]]
